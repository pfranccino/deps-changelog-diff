# deps-changelog-diff

Analyzes **what changed** between the version you use and the latest stable version of each
dependency, reading the official documentation from each project (GitHub Releases, AndroidX,
Firebase, Play services, Places...).

This is the **second step** of [`toml-deps-checker`](https://github.com/pfranccino/toml-deps-checker):
while that tool tells you *how outdated* each dependency is, this one tells you *what changed*.

It doesn't re-query Maven: it consumes the `dependency_status.json` generated by the first
script and, for each outdated dependency, collects the release notes.

## Source router (where notes come from)

| Type | Source | How |
|---|---|---|
| `maven`, `plugin` | **GitHub Releases API** | Discovers the repo from the POM's `<scm>`/`<url>` (follows the **parent** POM in multi-module projects) and fetches notes by tag, in Markdown. |
| `google` (AndroidX) | **crawl4AI** on developer.android.com | Page by group with `### Version X.Y.Z` headings. crawl4AI renders JS; if not installed, falls back to static HTML parsing (`requests`). |
| Firebase / Play services / Places | **official pages** | `firebase-bom` (Firebase release notes), `play-services-*` (Play services release guide) and `places` (Places SDK release notes). |
| any (fallback) | **crawl4AI** | Only for third-party sites with heavy JS. If it doesn't find real versions, returns **empty (`source: null`)** — never saves a page shell, to avoid false expectations. |

Only **stable versions** are compared (no alphas/betas/rc), and the range is
`(your_version, latest_stable]`: all intermediate stable versions, so you don't miss a
breaking change in between.

## Usage

### Prerequisites: generate `dependency_status.json`

This tool requires a `dependency_status.json` file generated by
[`toml-deps-checker`](https://github.com/pfranccino/toml-deps-checker):

```bash
git clone https://github.com/pfranccino/toml-deps-checker.git
cd toml-deps-checker
pip install -r requirements.txt
python check_dependencies.py /path/to/your/gradle/project
# This generates dependency_status.json with each dependency's status.
```

### Running the analysis

#### Linux / macOS (bash wrapper)

```bash
# Basic usage
./check-changelog.sh                                           # uses ./dependency_status.json
./check-changelog.sh --md changelog.md                         # also write a human-readable Markdown
./check-changelog.sh ./path/dependency_status.json -o out.json # custom paths

# Pass tokens as arguments
./check-changelog.sh --github-token ghp_YOUR_TOKEN
./check-changelog.sh --summarize --api-key sk-ant-YOUR_KEY --github-token ghp_YOUR_TOKEN

# Intel format (change intelligence)
./check-changelog.sh dependency_status.json --format intel --github-token ghp_YOUR_TOKEN
./check-changelog.sh dependency_status.json --format intel --summarize --api-key sk-ant-YOUR_KEY

# Compare heuristic vs LLM
./check-changelog.sh dependency_status.json --format intel --compare --api-key sk-ant-YOUR_KEY

# Scope LLM to specific deps
./check-changelog.sh dependency_status.json --format intel --summarize \
  --summarize-only "com.squareup.okhttp3:okhttp" --api-key sk-ant-YOUR_KEY

# All flags work through the wrapper
./check-changelog.sh dependency_status.json --format intel --summarize \
  --api-key sk-ant-YOUR_KEY --github-token ghp_YOUR_TOKEN \
  --no-crawl4ai -j 4 --timeout 30 --md changelog.md -q
```

#### Windows (PowerShell) — run Python directly

The `.sh` wrapper may fail due to CRLF line endings. Run Python directly:

```powershell
pip install -r requirements.txt
python -m playwright install chromium          # browser for crawl4AI (once)
python changelog-diff.py dependency_status.json --md changelog.md --github-token YOUR_TOKEN
```

#### Python module

```bash
python -m changelog_diff dependency_status.json --md changelog.md
```

### Tokens and credentials

All tokens can be passed as **CLI arguments** or **environment variables**:

| Parameter | CLI argument | Environment variable | Purpose |
|---|---|---|---|
| Anthropic API key | `--api-key sk-ant-...` | `ANTHROPIC_API_KEY` | Required for `--summarize` (direct Anthropic API) |
| LLM provider | `--provider anthropic\|bedrock` | `LLM_PROVIDER` | `anthropic` (default) or `bedrock` (AWS) |
| AWS region | `--aws-region us-east-1` | `AWS_REGION` | Region for Bedrock (optional, defaults to SDK config) |
| AWS profile | `--aws-profile default` | `AWS_PROFILE` | AWS credentials profile for Bedrock (optional) |
| GitHub token | `--github-token ghp_...` | `GITHUB_TOKEN` | Increases GitHub API rate limit (60 → 5000 req/h) |
| LLM model | `--model claude-haiku-4-5-20251001` | `ANTHROPIC_MODEL` | Model for summaries (default: `claude-haiku-4-5-20251001`) |

> **Use a GitHub token.** Without one, the API gives ~60 requests/hour, and with dozens of
> dependencies you'll exhaust it quickly (you'll see empty notes from rate limiting). A
> [classic token](https://github.com/settings/tokens) with no scopes is enough to read
> public repos.

**Examples:**

```bash
# Pass tokens as CLI arguments
python changelog-diff.py dependency_status.json \
  --github-token ghp_YOUR_TOKEN \
  --api-key sk-ant-YOUR_KEY \
  --summarize --md changelog.md

# Or use environment variables
export GITHUB_TOKEN=ghp_YOUR_TOKEN
export ANTHROPIC_API_KEY=sk-ant-YOUR_KEY
python changelog-diff.py dependency_status.json --summarize --md changelog.md

# Mix both — CLI takes precedence
export GITHUB_TOKEN=ghp_DEFAULT_TOKEN
python changelog-diff.py dependency_status.json --api-key sk-ant-YOUR_KEY --summarize
```

**Using [Amazon Bedrock](https://docs.aws.amazon.com/bedrock/) instead of direct Anthropic API:**

```bash
# Install the Bedrock extra (check-changelog.sh auto-installs it when --provider bedrock is passed)
pip install "anthropic[bedrock]>=0.40.0" boto3

# Uses default AWS credential chain
python changelog-diff.py dependency_status.json --summarize --provider bedrock

# Specify region and profile
python changelog-diff.py dependency_status.json --summarize \
  --provider bedrock --aws-region us-west-2 --aws-profile my-profile

# Or use environment variables
export LLM_PROVIDER=bedrock
export AWS_REGION=us-east-1
python changelog-diff.py dependency_status.json --summarize
```

### Bedrock credential resolution

The tool resolves AWS credentials using the same chain as the
[Anthropic Python SDK](https://github.com/anthropics/anthropic-sdk-python):

1. **Environment variables** — `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`,
   `AWS_SESSION_TOKEN`, `AWS_REGION`, `AWS_PROFILE`
   ([AWS docs](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-envvars.html))
2. **Claude Code settings** — the `env` block in `~/.claude/settings.json`,
   as configured by the [`/setup-bedrock` wizard](https://code.claude.com/docs/en/amazon-bedrock#sign-in-with-bedrock).
   Values from the `env` block are exported to the process environment so the
   SDK picks them up through its standard chain
3. **boto3 default credential chain** — `~/.aws/credentials`, IAM role, etc.
   ([boto3 docs](https://boto3.amazonaws.com/v1/documentation/api/latest/guide/credentials.html))

### Supported authentication methods

| Method | Environment variable | Reference |
|---|---|---|
| Access key + secret | `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` | [AWS docs](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-envvars.html) |
| Session token (STS) | `AWS_SESSION_TOKEN` | [AWS docs](https://docs.aws.amazon.com/IAM/latest/UserGuide/id_credentials_temp_use-resources.html) |
| Bedrock API key | `AWS_BEARER_TOKEN_BEDROCK` | [Anthropic docs](https://code.claude.com/docs/en/amazon-bedrock#2-configure-aws-credentials) |
| AWS profile / SSO | `AWS_PROFILE` | [AWS docs](https://docs.aws.amazon.com/cli/latest/userguide/cli-configure-profiles.html) |
| Custom gateway | `ANTHROPIC_BEDROCK_BASE_URL` | [Anthropic docs](https://code.claude.com/docs/en/amazon-bedrock) |
| Custom headers | `ANTHROPIC_CUSTOM_HEADERS` | [Anthropic docs](https://code.claude.com/docs/en/amazon-bedrock#aws-guardrails) |

When `ANTHROPIC_BEDROCK_BASE_URL` is set (gateway mode), the tool sends requests
to the custom endpoint with any `ANTHROPIC_CUSTOM_HEADERS` and skips local AWS
credential resolution — the gateway handles authentication.

Model names are auto-mapped to Bedrock format — no need to pass the full ID:

| CLI model name | Bedrock model ID |
|---|---|
| `claude-haiku-4-5-20251001` (default) | `us.anthropic.claude-haiku-4-5-20251001-v1:0` |
| `claude-sonnet-5` | `us.anthropic.claude-sonnet-5-20250514-v1:0` |

## Output

`changelog_diff.json`, one entry per coordinate:

```json
{
  "com.squareup.okhttp3:okhttp": {
    "type": "maven",
    "from": "4.12.0",
    "to": "5.0.0",
    "source": "github",
    "source_url": "https://github.com/square/okhttp/releases",
    "versions": [
      { "version": "5.0.0", "date": "2025-07-02", "url": "...", "notes": "..." }
    ]
  }
}
```

By default `notes` is the **raw text** from the official release notes, one entry per stable
version in the range. It's not a summary (unless you use `--summarize`).

## `intel` format (change-intel-1) — for an impact plugin

With `--format intel` the output switches from prose to **change intelligence** designed for
a plugin to search for impact in your repo (e.g. with the Android CLI):

```bash
# Free: heuristic (seeds + gates + approximate kind)
python changelog-diff.py dependency_status.json --format intel -o intel.json

# Enriched: adds replacement (old->new), refined kind and effort via LLM
python changelog-diff.py dependency_status.json \
  --format intel --summarize --api-key sk-ant-YOUR_KEY -o intel.json
```

Each dependency includes:

```json
{
  "alias": "google_services_auth",
  "from": "16.0.1", "to": "22.0.0", "jump": "major",
  "effort": "high", "confidence": "high",
  "seeds": {
    "packages": ["com.google.android.gms.auth.api.identity"],
    "types": ["AuthorizationRequest", "GoogleSignInClient"],
    "functions": ["requestOfflineAccess", "setPrompt", "getPrompt"]
  },
  "impact_seeds": {
    "packages": [], "types": [], "functions": ["requestOfflineAccess"]
  },
  "changes": [
    { "kind": "deprecation", "summary": "requestOfflineAccess() deprecated; use setPrompt()",
      "apis": ["AuthorizationRequest.Builder.requestOfflineAccess"],
      "replacement": "setPrompt", "version": "21.5.0", "ref": "..." }
  ],
  "raw": [ /* per-version notes, for auditing */ ]
}
```

- **`seeds`** = wide net of everything mentioned (packages/types/functions), extracted for
  free from backticks and links in the changelog.
- **`impact_seeds`** = subset that **breaks** (only `breaking`/`removal`/`deprecation`
  changes), excluding the replacement. This is what the plugin must search for. Approximate
  with heuristics, **clean with `--summarize`**.
- **`changes[].replacement`** = the old-to-new mapping (provided by `--summarize`).
- **`project_gates`** (at the top of the document) = build requirements (Java 17, minSdk N).
- **`effort` / `confidence`** = for prioritization and knowing when to distrust the data.

The plugin provides the **where** (searches your repo); this output provides the **what, why,
and how severe**.

### Two layers and cost comparison

- **Heuristic (free):** `seeds`, `gates`, approximate `kind`, raw `summary`. Always runs.
- **LLM (`--summarize`):** adds `replacement`, refines `kind`/`effort` and cleans noise.
  **Deduplicates by repo** (kotlin x5, ktor x7 -> 1 call) and can be scoped with
  `--summarize-scope major|all` or `--summarize-only "a,b"`. Classifying all majors costs
  pennies.
- **`--compare`:** runs both and reports, at no extra comparison cost, how many `replacement`
  the LLM added, how many `seeds` it cleaned, and how many `kind` it refined — to measure
  what you got from the LLM for what you paid.

## `--summarize` in raw format

In `--format raw`, `--summarize` adds a human-readable `summary` (breaking/deprecations/...)
per dependency. Requires `--api-key` or `ANTHROPIC_API_KEY`; without it, only raw notes are
produced.

## Cache

Changelogs are immutable per version, so they're cached by
`(coordinate, current_version..latest)` in `.changelog-cache/` (configurable with
`--cache-dir`; `none` disables it). **After updating the script, clear the cache** or use
`--cache-dir none`: the cache doesn't know the code changed.

## Flags

| Flag | Purpose |
|---|---|
| `--format raw\|intel` | `raw` = raw notes (default). `intel` = change-intel-1 schema. |
| `--summarize` | Enrich with LLM (requires API key or Bedrock credentials). |
| `--api-key` | Anthropic API key for LLM enrichment (or `ANTHROPIC_API_KEY` env var). |
| `--provider` | `anthropic` (default) or `bedrock` (AWS). Or `LLM_PROVIDER` env var. |
| `--aws-region` | AWS region for Bedrock (or `AWS_REGION` env var). |
| `--aws-profile` | AWS credentials profile for Bedrock (or `AWS_PROFILE` env var). |
| `--summarize-scope major\|all` | Which deps the LLM applies to in `intel` (default: majors only). |
| `--summarize-only "a,b"` | Comma-separated coordinates to enrich (ignores scope). |
| `--compare` | Run heuristic vs LLM (intel) and report the delta. |
| `--all` | Analyze all deps, not just outdated ones. |
| `--include-prereleases` | Include intermediate alphas/betas/rc (default: stables only). |
| `--model` | LLM model (or `ANTHROPIC_MODEL` env var). Default: `claude-haiku-4-5-20251001`. |
| `--github-token` | GitHub token for rate limiting (or `GITHUB_TOKEN` env var). |
| `--androidx-lang` | AndroidX language via `?hl=` param (default: `es-419`; `en` = English). |
| `--no-crawl4ai` | Don't use crawl4AI (avoids Playwright; AndroidX uses HTML parsing). |
| `--cache-dir` | Cache directory; `none` disables it. |
| `-o/--output`, `--md`, `-j/--jobs`, `--timeout`, `-q` | Output, parallelism, timeout, quiet mode. |

## Known limitations

- **Honest `null`:** binaries without a public per-version changelog — `AGP`,
  `google-services`, `googleid`, `integrity`, `appsflyer`, `nimbus-jose-jwt` — show
  `source: null` with no notes. We prefer `null` over a shell that misleads.
- **Firebase** returns the *table* of which artifact was bumped per BOM version, not the
  detail of each library (the page links to individual release notes).
- **`places`** may return `null` depending on how its page renders (extractor pending
  refinement — see roadmap).
- **`okhttp`** may collapse into a single note (the entire CHANGELOG) if its repo publishes
  few *releases*; the content is there, just poorly versioned (see roadmap).
- Source extractors for Firebase/Play services/Places depend on those official page
  structures; if Google restructures them, they may stop matching.
